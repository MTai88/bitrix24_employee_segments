# Сегменты рассылок по сотрудникам портала для Bitrix24

Модуль `mtai.employeesegments` добавляет источник **«Сотрудники портала»** в сегменты
модуля **«Маркетинг» (Рассылки, `/marketing/`)**. Позволяет собирать получателей рассылок
из **пользователей корпоративного портала** — без CRM (контактов и компаний).

Задача, которую решает модуль: когда Bitrix24 разворачивается как корпоративный портал,
CRM-сущностей нет, и штатные сегменты рассылок («Клиенты», «Лиды»), построенные на CRM,
не работают. Этот модуль даёт полноценный сегмент по сотрудникам: фильтры, счётчик
адресов, отправка писем и персонализация — всё как у штатных источников.

## Как это работает

Модуль регистрирует собственный коннектор
`Mtai\EmployeeSegments\Connector\Employee` через штатное событие модуля «Рассылки» —
**`OnConnectorList`** (см. `lib/eventhandler.php`). Коннектор наследует
`\Bitrix\Sender\Connector\BaseFilter` и поэтому автоматически появляется в стандартном
интерфейсе создания сегмента `/marketing/segment/`, а при отправке письма
попадает в общую цепочку (`Posting\Builder` → получатели → SMTP).

**Ядро Bitrix не изменяется** — только штатные точки расширения.

## Возможности фильтрации

| Фильтр | Описание |
|---|---|
| Активность | все / активные / неактивные |
| Отдел | один или несколько отделов, **включая все их подразделения** |
| Группа пользователей | одна или несколько групп (кроме системной «Все пользователи») |
| Должность | подстрока в поле «Должность» |
| Поиск | подстрока в ФИО, e-mail, логине или должности |
| Последний вход | диапазон дат |
| Дата регистрации | диапазон дат |

Дополнительно:

- Пользователи без e-mail автоматически исключаются из выборки.
- Пресеты: «Все сотрудники портала», «Активные сотрудники».
- Теги персонализации в теле письма: `#NAME#` (имя), `#EMPLOYEE_LOGIN#` (логин),
  `#EMPLOYEE_POSITION#` (должность), `#EMPLOYEE_WORK_PHONE#` (телефон).
- В получателях письма сохраняется привязка к пользователю (`USER_ID`), поэтому
  статистика отправок/прочтений связывается с сотрудником, а отписка работает штатно.

## Требования

- Bitrix24 («Корпоративный портал» или CRM) с установленным модулем **Рассылки** (`sender`).
- PHP 8.1+ (проверено на 8.3), Bitrix main 23+ (проверено на 26.750).
- Модуль **Внедрение** (`intranet`) не обязателен: без него фильтр по отделам просто
  не отображается, остальные фильтры работают.

## Установка

1. Скопируйте модуль в `local/modules/mtai.employeesegments`
   (имя папки должно совпадать с ID модуля — плоская структура, без подпапок):

   ```bash
   git clone git@github.com:MTai88/bitrix24_employee_segments.git local/modules/mtai.employeesegments
   ```

   либо просто положите содержимое репозитория в эту папку:

   ```
   local/modules/mtai.employeesegments/
   ├── install/
   ├── lang/
   └── lib/
   ```

2. Административный раздел → **Настройки → Настройки продукта → Модули**
   (`/bitrix/admin/modules.php`) → найдите «Сегменты рассылок: сотрудники портала» →
   **Установить**.

   Установка не создаёт таблиц: регистрируется запись модуля и обработчик события
   `sender::OnConnectorList`.

## Использование

1. Откройте **Маркетинг → Сегменты** (`/marketing/segment/`) → **Добавить сегмент**.
2. В блоке источников нажмите «Добавить источник» → выберите **«Сотрудники портала»**.
3. Задайте фильтры (например, пресет «Активные сотрудники» + отдел), нажмите «Применить» —
   увидите количество адресов.
4. Сохраните сегмент, затем создайте письмо
   (**Маркетинг → Рассылки**, `/marketing/letter/`) и укажите этот сегмент получателей.
5. В теле письма доступны теги: `#NAME#`, `#EMPLOYEE_LOGIN#`, `#EMPLOYEE_POSITION#`,
   `#EMPLOYEE_WORK_PHONE#`.

## Удаление

Настройки → Модули → «Сегменты рассылок: сотрудники портала» → **Удалить**.
Модуль не хранит собственных данных: удаляются только запись модуля и обработчик события.
Сегменты, созданные с источником «Сотрудники портала», останутся в списке сегментов,
но перестанут собирать адреса — удалите их вручную при необходимости.

### Добавление своих фильтров

Фильтры описаны в `lib/connector/employee.php`:

- `getUiFilterFields()` — поля UI-фильтра (формат `main.ui.filter`: `list`, `string`,
  `date`, `checkbox`, …);
- `getUsersFilter()` — превращение значений фильтра в D7-фильтр `UserTable`
  (см. документацию фильтров ORM: `=`, `%`, `>=`, вложенные блоки с `'LOGIC' => 'OR'`).

## Тестирование

Модуль проверен на стенде Bitrix24 26.x (корп. портал, PHP 8.3, MySQL 8, Mailpit):

- сегмент «Сотрудники портала» создаётся и считается в стандартном UI;
- письмо по сегменту доставляется сотрудникам, теги персонализации подставляются;
- отписки/чёрный список «Рассылок» применяются к сотрудникам штатным образом.
